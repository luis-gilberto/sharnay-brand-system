# Illustrations

Drawn work that sits outside the icon family.

Opens **only if needed**. Currently empty, and likely to stay that way.

---

**Holds** — diagrams, technical drawings, and any illustrated element that serves a genuine explanatory purpose. Lighting diagrams, session maps, and process drawings are the plausible candidates.

**Does not hold** — icons, which belong to `design-system/iconography` and its grid. Decorative drawing of any kind.

**A note on necessity** — this is a photography brand. Illustration competes with photography for the same attention and rarely wins the argument. The default answer to "should we illustrate this?" is no, and the exception is a diagram that explains something a photograph cannot.

Where illustration is justified, it obeys the same construction rules as the icon family: flat, frontal, single stroke weight, angles from the aperture set. It should read as an extension of the system, not as a guest in it.
